# Code Style Guide

This document defines the coding standards, formatting rules, and toolchains for the news-tldr.com project.

## Python (Pipeline)

- **Linter**: Use [Ruff](https://github.com/astral-sh/ruff) for the enforced lint, import-order, and modernization checks. The repository does not currently enforce Ruff's formatter; preserve surrounding formatting and keep patches focused.
- **Style Rules**:
  - Max line length: 120 characters.
  - Quote style: Double quotes `"` for strings unless single quotes prevent escaping.
  - Imports: Grouped by standard library, third-party, and local imports, sorted alphabetically within each group.
- **Type Annotations**:
  - All functions and public methods must have complete type annotations.
  - Prefer modern Python type syntax (e.g., `list[str]` instead of `List[str]`, `str | None` instead of `Optional[str]`).
  - Import `from __future__ import annotations` at the top of every file to enable postponed evaluation of type annotations.
- **Best Practices**:
  - Use parameterized queries for all SQLite interactions (no string formatting/concatenation for SQL).
  - Explicitly wrap I/O operations (like `socket.getaddrinfo` or heavy file reads) in `asyncio.to_thread` when executing in an async event loop.
  - Follow the fail-safe fallback pattern: log component-level failures and proceed with baseline content instead of crashing the run.

## Generated Frontend (HTML, JavaScript, CSS)

- **Renderer**: `pipeline/present.py` uses the Python standard library to render
  the complete static site. There is no Astro, Node package, component framework,
  or client-side build tool.
- **JavaScript**:
  - Keep browser behavior in the same-origin script generated by
    `pipeline/present.py`; do not add third-party runtime dependencies.
  - Use modern browser features where progressive failure leaves the static news
    content readable.
  - Treat upstream and LLM-generated strings as untrusted. Escape them in Python,
    allow only validated HTTP/HTTPS source URLs, and never interpolate raw content
    into executable JavaScript or HTML.
  - Check generated JavaScript syntax with Node after presentation changes.
- **CSS**:
  - Keep styles in the content-fingerprinted stylesheet generated by
    `pipeline/present.py`.
  - Use CSS custom properties and responsive layouts; respect reduced-motion
    preferences.
  - Avoid utility and component frameworks.
- **Static assets**: Checked-in images and icons live under `site/assets/`.
  Generated `dist/` output is ignored and must not be edited by hand.

## Tooling Commands

To check Python style:
```bash
# Run the enforced Ruff checks
./.venv/bin/python -m ruff check .

# Apply safe lint fixes when appropriate, then review the diff
./.venv/bin/python -m ruff check --fix .
```

After presentation changes, build without publishing and validate the generated
artifacts:

```bash
./.venv/bin/python -m pipeline.cli present --verbose --build-only
./.venv/bin/python -m pipeline.cli validate-data --verbose
```

## Editorial contracts

- Do not publish private `_evidence` passages. Public claim IDs map only to source IDs.
- Unknown citation IDs and oversized summary fields fail validation; never silently discard a bad citation or truncate a qualification.
- Read identity belongs to a meaningful story revision, not every rendering timestamp. Keep the one-second headline-read rule.
- Publisher IDs represent outlets, not proof of independent reporting. Do not relabel unknown provenance as independent.
- New evaluation output belongs under ignored `data/evaluations/`; keep synthetic fixtures and the human-review rubric in source control.
